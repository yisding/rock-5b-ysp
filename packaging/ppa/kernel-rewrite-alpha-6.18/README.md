# kernel-rewrite-alpha-6.18/ - Armbian-based rewrite kernel package

This directory defines the co-installable ROCK 5B 6.18 rewrite kernel package.
The replacement package now uses the exact Armbian current/forward-port source
line first, then applies the clean-room rewrite series.

> **Build-verified, not runtime-verified (2026-09-13):** the current pin built
> successfully on Launchpad's arm64 builders and has Published binaries, but
> it has not been installed or booted, and no KUnit, conformance, or hardware
> result belongs to it. It predates a dedicated local focused clean-archive
> build gate for this exact composite.

The Armbian snapshot was regenerated by the harness rather than reused from an
older release:

```sh
# with patch/kernel/archive/rockchip64-6.18/media-000{1,7}*.patch renamed
# to *.disabled first, exactly as build-kernel.sh does for our lanes
./compile.sh kernel-patches-to-git BOARD=rock-5b BRANCH=current \
    KERNELBRANCH=tag:v6.18.51
```

Both media patches must be disabled: they add the same rkvdec DT nodes and VSI
AV1 IOMMU driver that this composite's own forward-port commits carry, so
leaving them enabled makes the replay collide on file creation.

The 445-commit rewrite series — its forward-port prefix plus the rewrite
drivers — then replayed onto that snapshot without a single conflict. The
payload under `drivers/video/rockchip/` is byte-identical to
`rk3588-rewrite-6.18` at `7c38fc4ffaba7`, which is itself the maintained 6.18
tip rebased from `v6.18.42` to `v6.18.51` with no conflict at any step. The
prior tip is preserved at
`ysp-backup/rk3588-rewrite-6.18-before-6.18.51-20260913`.

## Build

```sh
bash kernel-drivers/scripts/build-kernel.sh ppa-rewrite-6.18
# (delegates to packaging/ppa/build-source-packages.sh kernel-alpha-6.18)
```

`build-source-packages.sh` archives the composite package pin above directly;
the repository's checked-out branch does not affect the export.

## Validation

Source-level only for the current pin. The rebase and composite replay are
conflict-accounted above, the packaged tree extracts and reports Linux 6.18.51,
and the config keeps both rewrite drivers and the KUnit suites built in while
disabling the conflicting vendor MPP/RGA drivers. No focused clean-archive
build gate, no full kernel compile, no Launchpad build result, and no install,
boot, rollback, or recovery evidence exists for this composite. Run the focused
gate via `rewrite-build-gate.sh` against a checkout of the composite head and
record the result in [`status.md`](../../../status.md) before treating this
package as buildable.

The superseded 6.18.38 pin did pass a warning-free clean archive build gate for
the Rockchip IOMMU provider, both KUnit-enabled rewrite objects, and the ROCK
5B DTB, plus source-package and full native arm64 image/DTB/headers builds.
That evidence belongs to that pin only.

## Runtime behavior and post-reboot validation

When this package's `6.18.51-ysp-alpha-6.18-rockchip64` kernel is booted,
`CONFIG_ROCKCHIP_MPP_REWRITE=y` and `CONFIG_ROCKCHIP_RGA_REWRITE=y` make the
rewrite drivers the built-in owners of `/dev/mpp_service` and `/dev/rga`. The
conflicting vendor MPP service and RGA drivers are disabled. Installing the
co-installable package is not sufficient evidence by itself: verify the
running release, rewrite debugfs ownership, boot log, hardware smoke workloads,
and counter deltas after reboot.

The exact preflight, quick smoke command for the maintained sibling-worktree
layout, standalone full suite, and forward-port-vs-rewrite comparison are in
[`conformance.md`](../../../kernel-drivers/tests/conformance.md#rewrite-acceptance-one-command).
Keep the existing Armbian or forward-port kernel available as the recovery boot
until this checklist passes.

The Debian helpers
[`install-kernel-packages.sh`](debian/scripts/install-kernel-packages.sh) and
[`write-maintainer-scripts.sh`](debian/scripts/write-maintainer-scripts.sh) are
kept byte-identical with the forward-port package and the other rewrite
package; `scripts/check-doc-consistency.py` enforces that invariant.
