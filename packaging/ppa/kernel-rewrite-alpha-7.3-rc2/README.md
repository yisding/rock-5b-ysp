# kernel-rewrite-alpha-7.3-rc2/ - Armbian-based rewrite kernel package

This directory defines the co-installable ROCK 5B 7.3-rc2 rewrite kernel
package. It applies Armbian's `rockchip64-bleedingedge` patch layer to official
`v7.3-rc2`, then applies the clean-room rewrite series. It supersedes
[`kernel-rewrite-alpha-7.2-rc5/`](../kernel-rewrite-alpha-7.2-rc5/README.md),
which was defined but never uploaded, and
[`kernel-rewrite-alpha-7.2-rc3/`](../kernel-rewrite-alpha-7.2-rc3/README.md).

> **Build-verified, not runtime-verified (2026-09-13):** this package built
> successfully on Launchpad's arm64 builders and has Published binaries, but
> it has not been installed or booted, and no KUnit, conformance, or hardware
> result belongs to it.

The Armbian snapshot was regenerated by the harness rather than replayed from
an older release:

```sh
./compile.sh kernel-patches-to-git BOARD=rock-5b BRANCH=bleedingedge \
    KERNELBRANCH=tag:v7.3-rc2
```

Armbian's `bleedingedge` branch selects `KERNEL_MAJOR_MINOR=7.3` as of build
checkout `2a53f158`, so this uses the real `archive/rockchip64-7.3` patch
directory rather than a cherry-picked 7.2 layer.

All 370 rewrite commits replayed onto that snapshot without a single conflict.
The rewrite payload under `drivers/video/rockchip/` is byte-identical to
`rk3588-rewrite-mainline` at `12a6a61b76aca`; the only tree difference outside
it is `include/uapi/linux/ipx.h`, which Armbian's own
`wireless-bring-back-headers` patch restores.

## Relationship to the maintained mainline rewrite tip

`rk3588-rewrite-mainline` itself moved for this package: its 370-commit local
range was rebased from `v7.2-rc6` to `v7.3-rc2`. That rebase needed exactly one
resolution, in `drivers/iommu/rockchip-iommu.c`. Upstream `414cb6f3ac621`
("iommu/rockchip: Drop global rk_ops in favor of per-device ops") removed the
file-scope `rk_ops` pointer that the rewrite's hardening commit also touched;
the port keeps upstream's removal and retains only the rewrite's forward
declaration of `rk_iommu_ops`. No remaining code refers to the removed global.
The prior tip is preserved at
`ysp-backup/rk3588-rewrite-mainline-before-7.3-rc2-20260913`.

## Build

```sh
bash kernel-drivers/scripts/build-kernel.sh ppa-rewrite-7.3-rc2
# (delegates to packaging/ppa/build-source-packages.sh kernel-alpha-7.3-rc2)
```

`build-source-packages.sh` archives the composite package pin above directly;
the repository's checked-out branch does not affect the export.

## Validation

Source-level only. The rebase and the composite replay are conflict-accounted
above, the packaged tree extracts and reports Linux 7.3.0-rc2, and the config
keeps both rewrite drivers and the KUnit suites built in while leaving the
conflicting stock RGA driver disabled. No focused clean-archive build gate, no
full kernel compile, no Launchpad build result, and no install, boot, rollback,
or recovery evidence exists for this composite. Run the focused gate via
`KERNEL_MAINLINE=<composite checkout> rewrite-build-gate.sh mainline` and record
the result in [`status.md`](../../../status.md) before treating this package as
buildable.

## Runtime behavior and post-reboot validation

When this package's `7.3.0-rc2-ysp-alpha-7.3-rc2-rockchip64` kernel is booted,
the MPP and RGA rewrite drivers are built in and own `/dev/mpp_service` and
`/dev/rga`; the conflicting stock RGA driver is disabled. Installing the
co-installable package does not prove that this release is running.

Use the package-identity, debugfs-owner, boot-log, smoke, full-suite, and paired
comparison checklist in
[`conformance.md`](../../../kernel-drivers/tests/conformance.md#rewrite-acceptance-one-command),
and retain a known-good recovery kernel until the runtime gate passes.

The Debian helpers
[`install-kernel-packages.sh`](debian/scripts/install-kernel-packages.sh) and
[`write-maintainer-scripts.sh`](debian/scripts/write-maintainer-scripts.sh) are
kept byte-identical with the forward-port package and the other rewrite
packages; `scripts/check-doc-consistency.py` enforces that invariant.
