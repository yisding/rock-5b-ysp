cross-project note behind each track — what the current state rests on, and

re-narrate that history here; a row that grows into a chronology has stopped

## Promotion rule

When a row becomes stable enough to be project-owned, move the detail to the
owning project doc and leave only a link here. When a fact can change without a
repo edit, keep the maintenance trigger in [`../status.md`](../status.md)'s
watchlist rather than only recording it here.

A row records the state, not the road to it. When new evidence supersedes a
row, rewrite the row and let the dated finding carry what changed — do not
append a correction paragraph below the table, which leaves the table itself
saying something the repo no longer believes.
