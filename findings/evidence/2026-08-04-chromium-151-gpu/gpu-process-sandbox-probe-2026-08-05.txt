Interpretation:

- Neither the browser nor GPU child command line contains --no-sandbox or
  --disable-gpu-sandbox. This is stock/default package behavior, not an
  operator-added sandbox override.
- NoNewPrivs=1 and an empty effective capability set are useful hardening, but
  Seccomp=0, Seccomp_filters=0, LSM=unconfined, and Chrome's own
  Sandboxed=false do not constitute an active Chrome GPU sandbox.
- The multiple-thread InitializeSandbox warning is a discriminator for the
  next investigation. It does not yet identify which Chrome, ANGLE/Mesa,
  libva, MPP, or RGA initialization step created the extra thread or prove
  that this warning alone caused the unsandboxed state.
